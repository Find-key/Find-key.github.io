前言

对于glibc的堆题.
get shell 的方法总是用任意地址写达成的.
本文讨论一些常见的调用链,用于任意地址写.

some of hook

适用版本: glibc<2.34
本质: 函数指针

__malloc_hook

简述:若调用malloc()函数时,__malloc_hook不为空,则直接调用__malloc_hook所指向的函数.

以下给出glibc2.23的malloc.c部分源码.

显然注意到在函数调用初期,
若__malloc_hook不为NULL,调用(*__malloc_hook)(),返回值作为malloc()的返回值.

__realloc_hook

简述:若调用realloc()函数时,__realloc_hook不为空,则直接调用__realloc_hook所指向的函数.

显然注意到在函数调用初期,
若__realloc_hook不为NULL,调用(*__realloc_hook)(),返回值作为realloc()的返回值.

__free_hook

简述:若调用free()函数时,__free_hook不为空,则直接调用__free_hook所指向的函数.

同样的,注意到在函数调用初期,
若__free_hook不为NULL,调用(*__free_hook)(),返回值作为free()的返回值.

exit_hook

exit_hook并不是官方所提供的,而是exit()调用链中所会用到的函数指针,

glibc 2.23的exit.c源码

注意到,exit()实际上是调用__run_exit_handlers()
而__run_exit_handlers()中不断调用exit_function_list中的函数.

其中一种思路是伪造exit_func_list或者往其中放入 one_gadget.

正常执行时,在exit_func_list会调用_dl_fini()函数.

在这个函数中调用了__rtld_lock_lock_recursive和__rtld_lock_unlock_recursive.

二者均位于_rtld_global结构体中,均为函数指针,名为__dl_rtld_lock_recursive和__dl_rtld_unlock_recursive.

这就是我们所寻找的”hook”函数指针.

综述

显然的,对于上述的几类hook指针,只要修改具体的值为one_gadget就可以到达 get shell 的效果.
